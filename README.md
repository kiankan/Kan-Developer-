# cPanel TeamKan — مدیریت cPanel/WHM از تلگرام

ربات تلگرامی مدیریت هاست که از طریق **API رسمی cPanel و WHM** به سرورهایتان وصل می‌شود: ایمیل، دیتابیس، دامنه، DNS، FTP، کران، SSL، نسخه‌ی PHP، بکاپ و مدیریت حساب‌های سرور — همه با منوی فارسی و **دکمه‌ی شیشه‌ای**.

- نصب فقط **یک دستور روی سرور** است و فقط **یک سؤال** دارد: توکن ربات.
- بعد از نصب، **همه‌چیز از داخل خود ربات تنظیم می‌شود** — هاست‌ها، توکن‌های cPanel/WHM، ادمین‌ها، سرور فعال.
- PHP خالص، **بدون هیچ وابستگی خارجی**. اتصال فقط با **API Token**؛ رمز حساب هیچ‌جا ذخیره نمی‌شود.

> این پروژه قبلاً یک چکر Fragment/TON بود و حالا کاملاً یک ابزار مدیریت cPanel است. نصب‌های قدیمی (با نام‌های `kan_checker` یا `kanpanel`) با اجرای همان دستور نصب، خودکار به `teamkan` منتقل می‌شوند و `.env` و سرورهای ذخیره‌شده‌شان حفظ می‌شود.

## نصب (روی سرور)

```bash
curl -fsSL https://raw.githubusercontent.com/kiankan/cpanel_teamkan/main/install.sh | sudo bash
```

(اگر از قبل root هستید، `sudo` را بردارید.)

فقط توکن ربات را می‌پرسد (از [@BotFather](https://t.me/BotFather) بگیرید)، دو سرویس systemd بالا می‌آورد و در آخر یک **کد نصب** چاپ می‌کند:

```
🤖 ربات را در تلگرام باز کنید و این کد را برایش بفرستید تا مالکش شوید:

    K7Q2-M9XD
```

کد را در تلگرام برای ربات بفرستید → شما مالک ربات می‌شوید و منو باز می‌شود. از این به بعد فقط شما (و هر ادمینی که خودتان اضافه کنید) به ربات دسترسی دارید و کد هم می‌سوزد.

بدون هیچ سوالی (مثلاً در اسکریپت):

```bash
ssh root@SERVER_IP 'curl -fsSL https://raw.githubusercontent.com/kiankan/cpanel_teamkan/main/install.sh | TELEGRAM_BOT_TOKEN=123456:ABC... bash'
```

اگر با `sudo` اجرا می‌کنید، متغیر را با `env` بدهید تا به bash برسد نه به curl:
`... | sudo env TELEGRAM_BOT_TOKEN=xxx bash`

برای **آپدیت** همین دستور را دوباره بزنید.

### مدیریت سرویس روی سرور

```
teamkan             منوی مدیریت
teamkan status     وضعیت دو سرویس + آدرس صفحه‌ی وضعیت
teamkan logs       لاگ زنده
teamkan code       نمایش کد نصب (اگر هنوز ربات را تحویل نگرفته‌اید)
teamkan token      تغییر توکن ربات
teamkan port       تغییر پورت صفحه‌ی وضعیت (پیش‌فرض 2000)
teamkan restart | stop | update | uninstall
```

## بعد از نصب، همه‌چیز از داخل ربات

`/start` را بفرستید تا منو بیاید. هیچ فایلی را دیگر لازم نیست دست بزنید.

**منو خودش را با وضعیت شما تطبیق می‌دهد** — دکمه‌ای که روی این هاست کار نمی‌کند اصلاً نشان داده نمی‌شود:

| وضعیت | چه می‌بینید |
| --- | --- |
| تازه نصب شده، هنوز هاستی نیست | فقط «⚙️ افزودن سرور / هاست» و «❓ راهنما» |
| هاست اشتراکی (توکن cPanel) | فقط کارهای همان حساب: خلاصه، دامنه، ایمیل، دیتابیس، فایل، FTP، کران، DNS، PHP، بکاپ |
| سرور WHM بدون کاربر مقصد | فقط کارهای سطح سرور + دکمه‌ی «🎯 انتخاب کاربر مقصد» |
| سرور WHM با کاربر مقصد | هر دو دسته با هم |

بقیه‌ی رفتار منو:

- **همان پیام ویرایش می‌شود**، نه اینکه با هر دکمه یک پیام تازه به چت اضافه شود.
- **هر صفحه دکمه‌ی بازگشت دارد** (بازگشت به منوی خودش + خانه).
- فهرست‌های واقعی (ایمیل‌ها، دیتابیس‌ها، فایل‌ها، رکوردهای DNS، حساب‌های WHM و ...) همان لحظه از سرور خوانده و به‌صورت دکمه نشان داده می‌شوند؛ فهرست بلند صفحه‌بندی می‌شود و هر جا خواستید می‌توانید مقدار را دستی هم بفرستید.
- «✨ قابلیت‌ها» دقیقاً می‌گوید روی همین هاست چه کارهایی ممکن است.
- «🧭 کارهای رایج» راهنمای گام‌به‌گام است: «سایت جدید راه بندازم»، «سورس بگذارم»، «دیتابیس بسازم و وصل کنم»، «ایمیل بسازم»، «SSL بگیرم»، «بکاپ بگیرم» — هر قدم یک دکمه است که مستقیم می‌برد به همان بخش.

| از داخل ربات | چه‌کار می‌کند |
| --- | --- |
| ⚙️ سرورها → ➕ افزودن سرور | هاست cPanel یا WHM را با آدرس/پورت/کاربر/توکن اضافه می‌کند و **قبل از ذخیره اتصال را تست می‌کند** |
| ⚙️ سرورها | جابه‌جایی بین چند هاست، حذف هاست، تست اتصال، ساخت کران روی هاست اشتراکی |
| 👮 ادمین‌ها | افزودن/حذف ادمین (با آیدی عددی تلگرام) |
| 🎯 انتخاب کاربر مقصد (منوی WHM) | تعیین اینکه کارهای سطح حساب روی کدام حسابِ سرور انجام شود |
| 🧾 لاگ عملیات | آخرین کارهایی که با ربات انجام شده |

### گذاشتن سورس روی هاست از داخل تلگرام

«📂 فایل‌ها» یک مرورگر فایل واقعی است: پوشه‌ها دکمه‌اند، با «⬆️ پوشه‌ی بالاتر» برمی‌گردید و می‌توانید مسیر را هم مستقیم تایپ کنید.

برای بالا بردن یک سایت:

1. «📂 فایل‌ها → 🗂 مرور فایل‌ها» و بروید داخل `public_html`
2. «⬆️ آپلود در همین پوشه» را بزنید و فایل `zip` سورس را همان‌جا در تلگرام بفرستید
3. بعد از آپلود، دکمه‌ی «🗜 باز کردن همین آرشیو» می‌آید — بزنید تا روی خود هاست باز شود

پوشه‌ی جدید و حذف فایل/پوشه هم از همان منو هستند. سقف حجم فایل در تلگرام ۲۰ مگابایت است.

نکته‌های امنیتی داخل ربات: عملیات خطرناک دکمه‌ی «✅ تأیید / ❌ انصراف» دارد، حذف کامل حساب در WHM نیاز به تایپ دوباره‌ی نام کاربری دارد، `/gen` رمز قوی می‌سازد، پیام حاوی رمز بعد از ثبت از چت پاک می‌شود، و کسی نمی‌تواند خودش را از فهرست ادمین‌ها حذف کند.

## قابلیت‌ها

**سطح حساب (توکن cPanel):**

| بخش | کارها |
| --- | --- |
| 📊 خلاصه | مصرف دیسک، پهنای‌باند، اینود و بقیه‌ی منابع + شمارش ایمیل/دیتابیس/FTP/دامنه |
| ✉️ ایمیل | لیست با مصرف و سهمیه، ساخت، حذف، تغییر رمز، تغییر سهمیه، فورواردها |
| 🗄 دیتابیس | لیست دیتابیس‌ها و کاربران، ساخت/حذف، تغییر نام دیتابیس و کاربر، رمز کاربر، دادن و گرفتن دسترسی، بررسی و تعمیر جدول‌های خراب، اتصال از راه دور (Remote MySQL) — منو پیشوند اجباری همان هاست را هم نشان می‌دهد |
| 🌐 دامنه | دامنه‌ی اصلی، ادان‌دامنه، ساب‌دامنه، پارک‌شده‌ها + ساخت/حذف ساب‌دامنه و ریدایرکت (۳۰۱/۳۰۲) |
| 🧭 DNS | نمایش کامل رکوردهای زون، افزودن رکورد (A/AAAA/CNAME/TXT/MX/NS)، حذف رکورد |
| 📂 فایل‌ها | مرور پوشه‌ها، آپلود فایل/سورس از تلگرام، باز کردن آرشیو روی هاست، ساخت پوشه، حذف |
| 📁 FTP | لیست با مصرف، ساخت، حذف |
| ⏰ کران | لیست، افزودن (با زمان‌بندی‌های آماده)، حذف، ایمیل خروجی |
| 🔒 SSL | گواهی‌های نصب‌شده، صادرکننده و روزهای باقی‌مانده + درخواست صدور/تمدید خودکار (AutoSSL) |
| 🐘 PHP | نسخه‌ی PHP هر دامنه + تغییر نسخه (MultiPHP) |
| 💾 بکاپ | شروع بکاپ کامل و فهرست بکاپ‌های موجود |

**سطح سرور (توکن WHM):** لیست حساب‌ها، جزئیات حساب، ساخت حساب، تعلیق/رفع تعلیق، تغییر رمز، تغییر پلن، **لینک ورود یک‌بارمصرف به cPanel کاربر**، حذف کامل حساب، پلن‌ها، بار سیستم، وضعیت سرویس‌ها و ری‌استارت سرویس. با یک توکن WHM می‌توانید همه‌ی کارهای سطح حساب را روی **هر کاربری** از آن سرور انجام دهید.

## ساخت API Token

- **یک حساب cPanel:** cPanel → **Security** → **Manage API Tokens** → *Create*. توکن فقط همان یک‌بار نشان داده می‌شود.
- **کل سرور (WHM):** WHM → **Development** → **Manage API Tokens** → *Generate Token*. توکن‌های WHM را می‌شود به ACL مشخص محدود کرد؛ فقط دسترسی‌های لازم را بدهید.

بعد در ربات: ⚙️ سرورها → ➕ افزودن سرور.

## پورت‌ها

دو چیز جدا از هم‌اند:

| چه چیزی | پورت | توضیح |
| --- | --- | --- |
| **سرویس خود ربات** | `2000` (قابل تغییر با `teamkan port`) | صفحه‌ی وضعیت `/` و سلامت JSON `/health` |
| **هاست‌هایی که مدیریت می‌کنید** | پورت خودشان | `2083` برای cPanel، `2087` برای WHM، و هرچه هاستتان داده (`2096`، `443`، ...) |

پورت هر هاست را می‌توانید داخل خود آدرس بنویسید؛ ربات خودش جدایش می‌کند:

```
server.example.com            → 2083 (پیش‌فرض cPanel)
server.example.com:2096       → 2096
https://cp.example.com:443/   → 443
```

چند هاست با پورت‌های متفاوت هم‌زمان کار می‌کنند — هر سرور پورت خودش را جدا نگه می‌دارد.

> ربات با long polling کار می‌کند و به هیچ پورت ورودی‌ای نیاز ندارد؛ پورت ۲۰۰۰ فقط صفحه‌ی وضعیت است. (وبهوک تلگرام هم فقط روی HTTPS و پورت‌های `443/80/88/8443` کار می‌کند، پس پورت ۲۰۰۰ مستقیماً وبهوک نمی‌گیرد.)

## خط فرمان (اختیاری)

هرچه در ربات هست، از ترمینال سرور هم در دسترس است — مفید برای اسکریپت و اتوماسیون:

```bash
cd /opt/teamkan

php cli.php ping                      # تست اتصال و اعتبار توکن
php cli.php summary                   # خلاصه‌ی منابع حساب
php cli.php email:list
php cli.php email:add info@example.com 'S3cret!' 512
php cli.php db:add user_shop && php cli.php dbuser:add user_admin 'S3cret!'
php cli.php db:grant user_admin user_shop
php cli.php dns:add example.com www A 203.0.113.10 300
php cli.php cron:add '*/5 * * * *' '/usr/local/bin/php /home/user/cron.php'
php cli.php php:set example.com ea-php82
php cli.php whm:accounts | php cli.php whm:login ali | php cli.php whm:status
php cli.php code                      # کد نصب  |  php cli.php admins
```

سوییچ‌های سراسری: `--server=<id>`، `--user=<user>` (کاربر مقصد روی WHM)، `--json`.

**تماس مستقیم با API** — هر تابعی که منو ندارد:

```bash
php cli.php uapi   Fileman list_files dir=/home/user/public_html
php cli.php whmapi listaccts search=shop searchtype=domain
php cli.php api2   MysqlFE listdbs
```

## حالت‌های دیگر (پیشرفته)

نصب پیشنهادی و پشتیبانی‌شده همان نصب روی سرور است، ولی این‌ها هم در مخزن هستند:

<details>
<summary>Docker</summary>

```bash
cp .env.example .env      # فقط TELEGRAM_BOT_TOKEN را پر کنید
docker compose up -d --build
docker compose exec bot php cli.php code
```

پوشه‌ی `data/` به‌صورت volume بیرون می‌ماند تا سرورهای اضافه‌شده با هر rebuild حفظ شوند.

</details>

<details>
<summary>هاست اشتراکی cPanel (بدون root)</summary>

روی هاستی که پروسه‌ی دائمی نمی‌شود اجرا کرد، ربات با یک کران هر دقیقه‌ای کار می‌کند: هر اجرا حدود ۵۵ ثانیه گوش می‌دهد (`poll.php`، با قفل فایلی و ذخیره‌ی offset).

```
* * * * * /usr/local/bin/php /home/user/teamkan/poll.php >/dev/null 2>&1
```

اگر ربات جای دیگری نصب است، همین کران را می‌توانید از داخل ربات روی آن حساب بسازید: ⚙️ سرورها → 🧩 اجرای ربات با کران روی هاست (یا `php cli.php selfhost:cron`).

با دامنه‌ی HTTPS، حالت وبهوک سریع‌تر است: فقط `webhook.php` داخل `public_html` باشد و بقیه‌ی پروژه بیرون از آن، بعد `php cli.php webhook:set https://example.com/kan/webhook.php` و حتماً `WEBHOOK_SECRET` را در `.env` پر کنید.

</details>

<details>
<summary>systemd دستی</summary>

```bash
sudo mkdir -p /opt/teamkan && cd /opt/teamkan
sudo git clone https://github.com/kiankan/cpanel_teamkan.git .
sudo cp .env.example .env    # فقط TELEGRAM_BOT_TOKEN
sudo cp deploy/teamkan-bot.service deploy/teamkan-web.service /etc/systemd/system/
sudo systemctl daemon-reload && sudo systemctl enable --now teamkan-bot teamkan-web
```

</details>

⚠️ هم‌زمان فقط یکی از حالت‌ها (سرویس دائمی / کران / وبهوک) را روشن نگه دارید، وگرنه دو نسخه به یک پیام جواب می‌دهند.

## تست‌ها

```bash
php tests/run.php          # تست‌های واحد، کاملاً آفلاین
php tests/integration.php  # تست سرتاسری رابط تلگرام
```

تست واحد لایه‌ی HTTP را با transport ساختگی جایگزین می‌کند: ساخت درخواست UAPI/WHM/API2، ترجمه‌ی خطاها، نرمال‌سازی پاسخ‌های ناهمگون cPanel، تجزیه‌ی آدرس و پورت هاست، دیکد base64 زون DNS، ذخیره‌ی سرورها، صفحه‌بندی دکمه‌ها و کامل‌بودن جدول جریان‌ها.

تست سرتاسری یک Bot API ساختگی و یک cPanel ساختگی روی TLS بالا می‌آورد (همه روی `127.0.0.1`، بدون اینترنت) و آپدیت‌های واقعی‌شکل را از همان مسیر همیشگی رد می‌کند: تحویل‌گرفتن ربات با کد نصب، منوها، فهرست‌های دکمه‌ای زنده، تأیید، اجرای واقعی عملیات روی پورت غیرپیش‌فرض، مدیریت ادمین‌ها و رد شدن کاربر غیرادمین.

## امنیت

- فقط API Token؛ رمز حساب cPanel هیچ‌جا ذخیره یا ارسال نمی‌شود.
- تا وقتی کسی ربات را با کد نصب تحویل نگرفته، ربات هیچ کاری انجام نمی‌دهد؛ کد یک‌بارمصرف است و بعد از استفاده عوض می‌شود.
- `data/` با `0700` و فایل‌های داخلش (`servers.json`، `admins.json`، `state.json`، `audit.log`) با `0600` نوشته می‌شوند. `.env` و `data/` در `.gitignore` هستند.
- توکن‌ها هیچ‌وقت کامل نمایش داده نمی‌شوند (`ABCD••••••WXYZ`) و در لاگ عملیات، رمزها با `***` جایگزین می‌شوند.
- بررسی گواهی SSL پیش‌فرض روشن است؛ خاموش‌کردنش فقط برای گواهی خودامضا توصیه می‌شود.
- توکن WHM را با کمترین ACL ممکن بسازید؛ توکن‌های cPanel به تمام قابلیت‌های همان حساب دسترسی دارند.

## نکات فنی

- UAPI روی `https://<host>:2083/execute/<Module>/<function>` با هدر `Authorization: cpanel <user>:<token>` و WHM API 1 روی `https://<host>:2087/json-api/<function>?api.version=1` با هدر `Authorization: whm <user>:<token>`. همه‌ی درخواست‌ها POST هستند تا رمزها در URL و لاگ وب‌سرور نیفتند.
- با توکن WHM، فراخوانی‌های سطح حساب از پراکسی `/json-api/cpanel` و با `cpanel_jsonapi_apiversion=3` به‌نام کاربر مقصد اجرا می‌شوند.
- بکاپ کامل روی نسخه‌های جدید با UAPI (`Backup::fullbackup_to_homedir`) گرفته می‌شود و روی نسخه‌های قدیمی با API1 قدیمی (`Fileman::fullbackup`)؛ فهرست بکاپ‌ها هم اگر تابعش نبود از روی خود پوشه‌ی هوم خوانده می‌شود.
- همه‌ی نسخه‌های cPanel یک‌جور نیستند: مثلاً روی خیلی از سرورها ماژول `Cron` اصلاً در UAPI وجود ندارد. کران، ساب‌دامنه و DNS خودکار روی API2 (`Cron::listcron`، `SubDomain::*`، `ZoneEdit::*`) برمی‌گردند و فقط وقتی خطا واقعاً «ماژول نیست» باشد — نه هر خطایی — این اتفاق می‌افتد تا خطای واقعی پنهان نشود.
- پاسخ‌های cPanel بین نسخه‌ها یک‌دست نیستند (گاهی لیست، گاهی دیکشنری، سهمیه گاهی مگابایت و گاهی بایت)؛ همه‌جا نرمال‌سازی می‌شود و ماژول‌های نصب‌نبوده فقط از خروجی حذف می‌شوند، نه اینکه کل دستور را بشکنند.
- رکوردهای DNS از `DNS::parse_zone` خوانده می‌شوند (فیلدها base64 هستند) و افزودن/حذف با `DNS::mass_edit_zone` انجام می‌شود که سریال فعلی SOA را لازم دارد؛ سریال خودکار خوانده می‌شود.
- فهرست‌های دکمه‌ای در وضعیت گفت‌وگو ذخیره می‌شوند و دکمه فقط شماره‌ی گزینه را می‌فرستد، چون تلگرام برای `callback_data` فقط ۶۴ بایت می‌دهد.
- پیام‌های بلند خودکار روی مرز خط تکه می‌شوند تا به سقف ۴۰۹۶ کاراکتری تلگرام نخورند، و گفت‌وگوهای نیمه‌کاره بعد از ۳۰ دقیقه منقضی می‌شوند.
- اگر `api.telegram.org` از سرورتان مستقیم در دسترس نیست، `TELEGRAM_API_BASE` را به آینه/پروکسی خودتان بدهید.
- پروژه هیچ وابستگی خارجی (Composer) ندارد؛ فقط `php-cli` با `curl`، `mbstring` و `json`.
