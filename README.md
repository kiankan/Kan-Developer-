# kan_checker

ربات چکر هش تراکنش TON و وضعیت/زمان باقی‌مانده مزایده‌های Fragment.com (یوزرنیم و شماره) — نوشته‌شده با PHP، بدون هیچ وابستگی خارجی (فقط `php-cli` با پسوندهای `curl`/`dom`/`mbstring`).

هیچ زمان‌بندی ثابتی نداره — فقط وقتی که پیام بفرستید (on-demand) جواب می‌ده، با شمارش‌معکوس دقیق تا ثانیه.

ربات با یک `ADMIN_ID` (آیدی عددی تلگرام) محدود می‌شه و فقط به همون آیدی پاسخ می‌ده — نصب هم فقط با دادن دو مقدار (توکن ربات + آیدی ادمین) کاملا خودکار انجام می‌شه، بدون هیچ مرحله‌ی دستی دیگه‌ای.

## قابلیت‌ها

**نیازی به دستور نیست** — کافیه یوزرنیم/لینک/هش/آدرس ولت/مقدار ارز رو مستقیم برای ربات بفرستید، خودش نوع ورودی رو تشخیص می‌ده:

- یوزرنیم، لینک fragment.com یا لینک دیپ‌لینک والت (مثل Tonkeeper) →
  وضعیت مزایده، بالاترین پیشنهاد و زمان دقیق باقی‌مانده (روز/ساعت/دقیقه/ثانیه).
  لینک‌هایی مثل `https://app.tonkeeper.com/dapp/https%3A%2F%2Ffragment.com%2Fusername%2F<username>`
  به‌صورت خودکار دیکد و به لینک fragment.com واقعی تبدیل می‌شن.

- **گیفت‌های NFT تلگرام** — لینک `t.me/nft/<slug>`، لینک `fragment.com/gift/<slug>`، یا فقط خود اسلاگ (مثل `durovscap-1142`) →
  اسم، شماره، مالک، Model/Backdrop/Symbol و قیمت. اگه `GIFT_ASSET_API_KEY` تنظیم شده باشه (پایین‌تر توضیح داده شده)، قیمت **کف بازار به تفکیک Model، Backdrop و Model+Backdrop، روی Tonnel/Portals/MRKT/GetGems** با تومان/دلار/TON/⭐️استارز نشون داده می‌شه؛ بدون کلید، فقط آخرین قیمت فروش ثبت‌شده روی خود Fragment (اگه موجود باشه).

- هش تراکنش TON (hex یا base64) → وضعیت تراکنش (موفق ✅ یا ناموفق ❌، زمان، حساب، کارمزد) از طریق [tonapi.io](https://tonapi.io).

- آدرس ولت **TON، Bitcoin، Ethereum یا Tron** → موجودی ولت به همون ارز، تومان (نرخ لحظه‌ای والکس) و دلار. فرمت آدرس به‌صورت خودکار تشخیص داده می‌شه (TON: هم `UQ...`/`EQ...` و هم `0:...`؛ BTC: `1...`/`3...`/`bc1...`؛ ETH: `0x...`؛ TRX: `T...`).

- **مقدار + اسم ارز** (مثل `1 ton`، `5 btc`، `10 تتر`، `3 بیتکوین`) → قیمت لحظه‌ای به تومان و دلار. اعداد لاتین و فارسی هردو پشتیبانی می‌شن؛ اعداد نوشتاری («پنج») فعلاً نه.

دستورهای صریح هم برای هر کدوم هست، اگه ترجیح می‌دید: `/auction` `/gift` `/tx` (یا `/hash`) `/wallet` `/check`.

- `/status` — وضعیت کوتاه ربات (فعال/غیرفعال، ساعت سرور، نسخه‌ی PHP)؛ برخلاف بقیه‌ی دستورها **برای همه در دسترسه**، حتی اگه `ADMIN_ID` تنظیم شده باشه.

- `/admin` (فقط ادمین، همیشه — این پنل و ویرایش‌ها هیچ‌وقت با حالت عمومی باز نمی‌شن) — پنل مدیریت با دکمه‌های شیشه‌ای: وضعیت ربات، چکر مزایده، چکر گیفت، چکر هش، چکر ولت، چکر قیمت ارز، **سوییچ حالت عمومی** (پایین‌تر توضیح داده شده)، **ویرایش متن‌ها و قالب‌ها** (بدون نیاز به تغییر کد یا دیپلوی)، راهنما. چون ورودی‌ها خودکار تشخیص داده می‌شن، بعد از زدن دکمه‌های چکر فقط کافیه مقدار مدنظرتون رو (بدون دستور) بفرستید.

### حالت عمومی (باز کردن ربات برای همه)

با `ADMIN_ID` تنظیم‌شده، ربات پیش‌فرض فقط به خود ادمین جواب می‌ده. از `/admin` دکمه‌ی «🔒 حالت عمومی: خاموش» رو بزنید تا روشن بشه — از اون لحظه همه می‌تونن از چکرها (مزایده/گیفت/هش/ولت/قیمت) استفاده کنن، بدون نیاز به تغییر `.env` یا ری‌استارت سرویس. پنل ادمین و ویرایش متن‌ها همیشه، حتی با حالت عمومی روشن، فقط برای خود ادمین (همون `ADMIN_ID`) باز می‌مونه. برای بستنش دوباره از همون دکمه استفاده کنید.

همه‌چیز به‌صورت CLI هم در دسترسه (بدون نیاز به تلگرام):

```bash
php cli.php auction <username>
php cli.php gift <t.me/nft link | fragment.com/gift link | slug>
php cli.php tx <hash>
php cli.php wallet <address>              # TON / BTC / ETH / TRX
php cli.php price "1 ton"                 # یا "5 btc" و مشابه
php cli.php check <هرکدوم از بالا>
```

### ویرایش متن‌ها و قالب گیفت از پنل ادمین

از `/admin` گزینه‌ی «✏️ ویرایش متن‌ها و قالب‌ها» رو بزنید — لیستی از متن‌های قابل‌ویرایش میاد:

- **پیام خوش‌آمد/راهنما** (`/start`, `/help`)
- **سربرگ / بخش قیمت هر ویژگی / پابرگ** پیام گیفت — این سه تا با هم قالب کامل پاسخ گیفت رو می‌سازن. پیش‌فرض ساده و بدون نقل‌قول (`<blockquote>`) هست، فقط تیتر بولده؛ ولی چیزی که بفرستید **دقیقاً همون‌طور که هست ذخیره و استفاده می‌شه** — می‌تونید کلاً یه متن ساده‌ی بدون تگ بفرستید، یا اگه خواستید از تگ‌های HTML تلگرام مثل `<b>بولد</b>` یا `<blockquote>نقل‌قول</blockquote>` استفاده کنید. جاهای خالی `{name}` `{label}` `{value}` `{toman}` `{usd}` `{ton}` `{stars}` `{source}` `{date}` هم خودکار پر می‌شن.
- **نرخ هر استارز به دلار** (عدد ساده، پیش‌فرض `0.015`) — برای تبدیل قیمت گیفت به ⭐️Stars.

هر کدوم رو بزنید، متن جدید رو بفرستید (یا `/cancel` برای انصراف) و فوراً ذخیره می‌شه.

## نصب روی سرور (VPS) — با منوی مدیریت

نصب اولیه، به‌عنوان root روی سرور (مثلا همون لحظه‌ای که با SSH وارد شدید)، تعاملی — فقط توکن و آیدی ادمین رو می‌پرسه:

```bash
bash <(curl -Ls https://raw.githubusercontent.com/kiankan/kan_checker/main/kancheckerctl) install
```

یا کاملا خودکار در یک خط SSH، بدون هیچ سوالی — فقط همین دو مقدار رو می‌دید و بقیه‌ش خودکاره:

```bash
ssh root@SERVER_IP 'TELEGRAM_BOT_TOKEN=xxx ADMIN_ID=123456789 bash <(curl -Ls https://raw.githubusercontent.com/kiankan/kan_checker/main/kancheckerctl) install'
```

(آیدی عددی ادمین رو از @userinfobot توی تلگرام بگیرید — یوزرنیم کافی نیست.)

این دستور `php-cli` و پسوندهای لازم و `git` رو نصب می‌کنه، پروژه رو در `/opt/kan_checker` کلون می‌کنه، `.env` رو با توکن و آیدی ادمین می‌سازه، سرویس systemd رو می‌سازه و روشنش می‌کنه، و خودش رو به‌صورت دستور `kancheckerctl` در سیستم ثبت می‌کنه — همه‌چیز در یک اجرا، بدون مرحله‌ی دستی دیگه.

از این به بعد کافیه فقط بنویسید:

```bash
kancheckerctl
```

و این منو باز می‌شه:

```
==== kan_checker — منوی مدیریت سرور ====
1) نصب
2) آپدیت
3) شروع سرویس
4) توقف سرویس
5) ری‌استارت سرویس
6) وضعیت سرویس
7) نمایش لاگ (زنده)
8) تنظیم/تغییر توکن و آیدی ادمین
9) حذف کامل
0) خروج
```

هر گزینه رو هم می‌شه مستقیم بدون منو صدا زد، مثلاً برای آپدیت:

```bash
sudo kancheckerctl update
```

یا: `kancheckerctl status` / `kancheckerctl logs` / `kancheckerctl restart` / `kancheckerctl set-token` / `kancheckerctl uninstall`

> اگر قبلاً نسخه‌ی پایتونی این پروژه را نصب کرده بودید: کافیست `kancheckerctl update` را بزنید — نصب قدیمی را تشخیص می‌دهد، پاک می‌کند و PHP را جای آن می‌نشاند.
>
> اگر بعد از آپدیت خود دستور `kancheckerctl` با خطای `syntax error` مواجه شد (نسخه‌های خیلی قدیمی این باگ را داشتند، در نسخه‌ی فعلی رفع شده)، به‌جای آن یک‌بار مستقیماً از روی گیت‌هاب اجرا کنید تا باینری نصب‌شده رو تعمیر کنه:
> ```bash
> bash <(curl -Ls https://raw.githubusercontent.com/kiankan/kan_checker/main/kancheckerctl) update
> ```

## نصب روی هاست (Docker) — یک دستور، هم نصب هم آپدیت

روی هر هاست/سروری با SSH (Railway، Render، Fly.io، یا هر VPS):

```bash
bash <(curl -Ls https://raw.githubusercontent.com/kiankan/kan_checker/main/install.sh)
```

اگه Docker نصب نباشه، خودش به‌صورت خودکار نصبش می‌کنه؛ بعد توکن و آیدی ادمین رو می‌پرسه و کانتینر رو بالا میاره.

یا کاملا خودکار در یک خط، بدون هیچ سوالی:

```bash
ssh root@SERVER_IP 'TELEGRAM_BOT_TOKEN=xxx ADMIN_ID=123456789 bash <(curl -Ls https://raw.githubusercontent.com/kiankan/kan_checker/main/install.sh)'
```

برای **آپدیت** بعدی، کافیه دقیقاً همین دستور رو دوباره اجرا کنید — پروژه رو pull می‌کنه و کانتینر رو با تغییرات جدید rebuild و ریستارت می‌کنه (توکن و آیدی ادمین قبلی رو هم حفظ می‌کنه، نیازی به دوباره وارد کردن نیست).

لاگ زنده: `cd ~/kan_checker && docker compose logs -f`

## نصب روی هاست اشتراکی/cPanel (بدون SSH پایدار، فقط PHP)

اگه هاستتون فقط PHP داره و نمی‌تونید یک پروسه‌ی همیشه‌روشن (مثل بالا) اجرا کنید، از حالت **webhook** استفاده کنید — فقط یک درخواست HTTP وقتی کاربر پیام می‌ده اجرا می‌شه، دقیقا مثل هر اسکریپت PHP معمولی:

1. فایل‌های پروژه رو (از جمله `.env` با `TELEGRAM_BOT_TOKEN` و `ADMIN_ID`) روی هاست آپلود کنید، طوری که `webhook.php` از یک آدرس HTTPS عمومی در دسترس باشه (مثلاً `https://example.com/kan_checker/webhook.php`).
2. یک‌بار این دستور رو (از یک ترمینال PHP، مثلاً از طریق SSH موقت یا Terminal پنل هاست) بزنید تا تلگرام رو به اون آدرس وصل کنید:
   ```bash
   php cli.php webhook:set https://example.com/kan_checker/webhook.php
   ```
   برای قطع وبهوک: `php cli.php webhook:delete`

از این به بعد تلگرام خودش هر پیام رو مستقیم به `webhook.php` می‌فرسته و نیازی به هیچ پروسه یا کرون‌جابی نیست.

## گرفتن کلید GiftAsset (اختیاری — برای قیمت چندبازاره‌ی گیفت‌ها)

قیمت کف Tonnel/Portals/MRKT/GetGems به تفکیک Model/Backdrop از سرویس شخص‌ثالث [giftasset.gifts](https://giftasset.gifts) میاد که نیاز به API Key داره. این کاملاً اختیاریه و **پیش‌فرض خاموشه** — بررسی کردیم و راه ساده‌تری هم نیست: خود Tonnel و Portals هم به‌جای API Key ساده، به یه توکن نشست شخصی تلگرام (Telegram session token) نیاز دارن که گرفتنش از حساب واقعیتون ریسک بیشتری داره تا یه کلید API معمولی.

اگه با وجود این خواستید امتحانش کنید:

1. توی تلگرام برید سراغ ربات [@giftasset_api_tokens_bot](https://t.me/giftasset_api_tokens_bot) و درخواست کلید بدید، یا با [@andril10](https://t.me/andril10) هماهنگ کنید. **این سرویس مستقل و خارج از کنترل ماست** — قبل از دادن هر اطلاعاتی خودتون اعتبارش رو بسنجید، و ترجیحاً با یه اکانت فرعی/تست پیش برید نه اکانت اصلی.
2. کلیدی که می‌دن رو بذارید توی `.env`: `GIFT_ASSET_API_KEY=your-key-here`
3. سرویس رو ری‌استارت کنید: `kancheckerctl restart` (یا برای Docker: `docker compose restart`).

بدون این کلید (حالت پیش‌فرض)، چکر گیفت همچنان کار می‌کنه ولی به‌جای قیمت چندبازاره فقط آخرین فروش ثبت‌شده روی خود Fragment رو نشون می‌ده (اگه اون گیفت اونجا فروخته شده باشه؛ خیلی از گیفت‌ها اصلاً روی Fragment لیست نشدن).

## نصب دستی (اگر نخواستید از اسکریپت‌ها استفاده کنید)

<details>
<summary>systemd دستی</summary>

```bash
sudo mkdir -p /opt/kan_checker
cd /opt/kan_checker
sudo git clone https://github.com/kiankan/kan_checker.git .
sudo cp .env.example .env   # و توکن و آیدی ادمین رو داخلش بگذارید
```

برای هاست‌هایی که از `Procfile` پشتیبانی می‌کنن (مثل Railway بدون Docker)، همون فایل `Procfile` موجود در ریشه‌ی پروژه استفاده می‌شه (`worker: php bot.php`) — کافیه متغیرهای محیطی `TELEGRAM_BOT_TOKEN` و `ADMIN_ID` رو در پنل هاست تنظیم کنید.

## نکات فنی

- داده‌ی مزایده مستقیماً از HTML صفحه‌ی Fragment.com خونده می‌شه (Fragment فعلاً API عمومی رسمی نداره)، پس اگر ساختار سایت عوض بشه ممکنه پارسر نیاز به به‌روزرسانی داشته باشه.
- زمان پایان مزایده از attribute استاندارد `datetime` روی تگ `<time class="tm-countdown-timer">` صفحه‌ی Fragment خونده و به ثانیه‌ی دقیق تبدیل می‌شه.
- برای تراکنش‌های TON از API عمومی و رایگان [tonapi.io](https://tonapi.io) استفاده شده (نیازی به کلید API برای استفاده‌ی سبک نیست).
- اگر `ADMIN_ID` در `.env` تنظیم نشده باشه، ربات به پیام هر کسی توی تلگرام پاسخ می‌ده (به جز اینکه `/status` همیشه برای همه بازه) — تمام روش‌های نصب بالا این مقدار رو ازتون می‌گیرن و تنظیمش می‌کنن.
- پروژه هیچ وابستگی خارجی (Composer/کتابخونه) نداره؛ فقط از پسوندهای استاندارد PHP (`curl`, `dom`, `mbstring`, `json`) استفاده می‌کنه که تقریباً روی همه‌ی هاست‌ها فعاله.
- نرخ تومان و دلار در چکر ولت با یک درخواست به API عمومی [والکس](https://api.wallex.ir/v1/markets) (جفت‌ارزهای `<COIN>TMN` و `<COIN>USDT`، مثلاً `BTCTMN`) خونده می‌شه؛ اگه از سرورتون در دسترس نباشه، فقط موجودی سکه نشون داده می‌شه و به‌جای هرکدوم یه پیام «rate unavailable» میاد — یعنی خرابی این بخش هیچ‌وقت باعث خطای کلی نمی‌شه. (قبلاً از نوبیتکس استفاده می‌شد، ولی دامنه‌ی `api.nobitex.ir` روی خیلی از VPSهای خارج از ایران اصلاً DNS resolve نمی‌شه؛ والکس این مشکل رو نداشت.)
- برای موجودی ولت‌ها از این APIهای عمومی و رایگان (بدون نیاز به کلید) استفاده شده: TON از [tonapi.io](https://tonapi.io)، بیت‌کوین از [blockstream.info](https://blockstream.info/api)، اتریوم از یک RPC عمومی ([publicnode.com](https://ethereum-rpc.publicnode.com))، و ترون از [TronGrid](https://api.trongrid.io).
- ویژگی‌های گیفت (اسم، شماره، مالک، Model/Backdrop/Symbol) مستقیم از صفحه‌ی عمومی `t.me/nft/<slug>` خونده می‌شه — همون صفحه‌ای که با فرستادن یک گیفت لینک می‌گیرید، بدون نیاز به لاگین یا کلید.
- تشخیص یوزرنیم از اسلاگ گیفت (`durovscap-1142`) بر پایه‌ی این قانونه که یوزرنیم تلگرام هیچ‌وقت خط‌تیره نداره، پس هیچ ابهامی بینشون نیست.
- قیمت‌گذاری گیفت دو حالته: با `GIFT_ASSET_API_KEY` از giftasset.gifts (کف بازار Tonnel/Portals/MRKT/GetGems به تفکیک ویژگی)، بدون کلید از آخرین فروش خود Fragment (`fragment.com/gift/<slug>`، همون پارسر مزایده‌ی یوزرنیم/شماره که یه جدول ویژگی اضافه هم داره). چون ساختار دقیق پاسخ giftasset.gifts بدون کلید واقعی قابل تست نبود، تطبیق Model/Backdrop توش heuristic هست — اگه خروجی درست نبود، با کلید واقعی تست کنید و به من بگید تا دقیقش کنم.
- برای چکر قیمت آزاد ارز (`1 ton`، `5 btc`، ...) همون منبع قیمت والکس که برای ولت استفاده می‌شه دوباره استفاده می‌شه، بدون درخواست اضافه.
- پیام خوش‌آمد (`/start`, `/help`) توی `data/texts.json` روی دیسک ذخیره می‌شه (این مسیر توی `.gitignore` هست، پس با آپدیت پاک نمی‌شه)؛ از پنل ادمین قابل تغییره، بدون نیاز به ویرایش کد.
- روی سرور، بات با `bot.php` که `getUpdates` رو با long-polling (timeout سی‌ثانیه‌ای) صدا می‌زنه اجرا می‌شه — یعنی بین درخواست‌ها منتظر می‌مونه و CPU مصرف نمی‌کنه، نه اینکه مدام در یک حلقه‌ی تنگ چک کنه. یونیت systemd هم برای مصرف کم منابع تنظیم شده: `Nice=10` (اولویت پایین‌تر از کارهای مهم‌تر سیستم)، `CPUQuota=25%` و `MemoryMax=128M` (سقف مصرف)، و `StartLimitIntervalSec=60`/`StartLimitBurst=5` که اگه به هر دلیلی سرویس مدام کرش کنه (مثلاً توکن اشتباه)، بعد از ۵ بار تلاش توی ۶۰ ثانیه، systemd به‌جای crash-loop بی‌نهایت متوقفش می‌کنه؛ می‌تونید با `kancheckerctl status`/`logs` علتش رو ببینید و بعد از رفعش `kancheckerctl restart` بزنید.
