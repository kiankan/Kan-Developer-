# Kan Developer

مخزن ابزارهای توسعهٔ **Kan**. در وضعیت فعلی، این مخزن شامل گردش‌کار GitHub Actions برای بررسی اجرای ناموفق و ارسال گزارش به GitHub Issues و تلگرام است.

> **توجه:** پروژهٔ قدیمی ربات مدیریت cPanel/WHM با نام TeamKan از شاخهٔ اصلی حذف شده است و بخشی از کد فعلی این مخزن نیست.

## قابلیت فعلی

- تشخیص اجرای ناموفق گردش‌کارهای GitHub Actions.
- دریافت اطلاعات اجرای ناموفق و تلاش برای خواندن لاگ‌ها.
- درخواست تحلیل علت احتمالی خطا از OpenAI API.
- ساخت گزارش در بخش Issues مخزن و جلوگیری از ایجاد گزارش تکراری برای یک شناسهٔ اجرا (run ID).
- ارسال هشدار به گفت‌وگوی تلگرام در صورت پیکربندی اسرار مربوطه.
- اجرای دستی گردش‌کار برای بررسی یک شناسهٔ run_id مشخص.

**این ابزار فایل‌های پروژه را اصلاح نمی‌کند، پچ را اعمال نمی‌کند و چیزی را خودکار ادغام نمی‌کند.** پیشنهادهای تولیدشده را قبل از هر اقدامی بررسی و آزمایش کنید.

## راه‌اندازی

### ۱. افزودن اسرار مخزن

در [Settings → Secrets and variables → Actions](https://github.com/kiankan/Kan-Developer-/settings/secrets/actions) این اسرار را بسازید:

| نام | کاربرد |
| --- | --- |
| OPENAI_API_KEY | کلید API برای تحلیل لاگ‌ها با OpenAI |
| TELEGRAM_BOT_TOKEN | توکن ربات اختصاصی تلگرام |
| TELEGRAM_CHAT_ID | شناسهٔ گفت‌وگوی مقصد برای دریافت هشدار |

برای گزارش‌گیری GitHub از GITHUB_TOKEN داخلی Actions استفاده می‌شود. توکن‌ها و کلیدها را در فایل‌ها، کامیت‌ها یا Issueها قرار ندهید.

### ۲. ساخت ربات تلگرام

1. در تلگرام به حساب رسمی [@BotFather](https://t.me/BotFather) بروید و دستور /newbot را بفرستید.
2. توکن ربات را محرمانه نگه دارید.
3. گفت‌وگوی خصوصی با ربات را باز کنید و /start بفرستید؛ برای گروه یا کانال، ربات را اضافه کنید و دسترسی ارسال پیام بدهید.
4. شناسهٔ مقصد را به‌عنوان TELEGRAM_CHAT_ID ثبت کنید.

راهنمای تکمیلی: [راهنمای راه‌اندازی تلگرام](docs/telegram-autofix-setup.md).

### ۳. بررسی و آزمایش

1. به بخش [Actions](https://github.com/kiankan/Kan-Developer-/actions) بروید.
2. گردش‌کار **Kan GitHub AutoFix** را باز کنید.
3. برای اجرای دستی، گزینهٔ **Run workflow** را بزنید و شناسهٔ اجرای ناموفق را در فیلد run_id وارد کنید.
4. لاگ اجرا را بررسی کنید. در صورت پیکربندی درست، پیام **Telegram failure alert sent.** نشان می‌دهد که API تلگرام ارسال پیام را پذیرفته است.

اجرای دستی با یک run_id قدیمی لزوماً هشدار جدید تولید نمی‌کند؛ اگر برای همان اجرا Issue گزارش قبلی وجود داشته باشد، گردش‌کار برای جلوگیری از تکرار زودتر خارج می‌شود. برای آزمون سرتاسری، از اجرای ناموفق جدید و بی‌خطر استفاده کنید.

## ساختار فعلی مخزن

- .github/workflows/kan-autofix.yml — گردش‌کار تحلیل خطا و اعلان.
- docs/telegram-autofix-setup.md — راهنمای تنظیم ربات و اسرار.

## امنیت و محدودیت‌ها

- محتوای لاگ و مخزن ممکن است غیرقابل‌اعتماد باشد؛ تحلیل هوش مصنوعی را پیشنهاد بدانید، نه دستور اجرایی.
- اسرار را در خروجی‌ها یا پیام‌های عمومی منتشر نکنید.
- این گردش‌کار فقط گزارش می‌سازد و اعلان می‌فرستد؛ تغییر کد یا ادغام خودکار انجام نمی‌دهد.
- نتیجهٔ موفق اجرای واقعی هنوز باید در محیط مخزن بررسی شود.
